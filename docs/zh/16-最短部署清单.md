# 16 — 最短部署清单

> 前提：`git status` 为 **working tree clean**，且与 `origin/main` 同步。  
> 项目根目录存在 `.env`（从 `.env.example` 或 `.env.development.example` 复制后填写密钥）。

---

## 场景 A：全 Docker 部署（生产 / 预览）

适合：演示、预发、单机完整栈。

**一键脚本（推荐）：**

```powershell
cd E:\AI知识平台\knowflow-ai
.\deploy_all.ps1
```

脚本会依次：构建镜像 → 启动服务 → 健康检查 → `e2e_acceptance.py` → 容器内 `pytest`。

手动步骤：

```powershell
cd E:\AI知识平台\knowflow-ai

# 1. 构建镜像
docker compose build

# 2. 启动全部服务（含 frontend）
docker compose up -d

# 3. 检查容器
docker ps
```

**应看到（核心）：**

| 容器 | 端口（宿主机） |
|------|----------------|
| knowflow-postgres | 5432 |
| knowflow-redis | 6379 |
| knowflow-chromadb | 8001 |
| knowflow-backend | 8000 |
| knowflow-celery-worker | — |
| knowflow-frontend | 3000 → 容器 80 |

**可选 — 生产 Nginx（profile）：**

```powershell
docker compose --profile production up -d
# 额外启动 knowflow-nginx，默认 80 端口（确保未被占用）
```

**健康检查：**

```powershell
curl http://localhost:8000/api/health
# 预期: {"status":"ok", ...}
```

**访问：**

- 前端：http://localhost:3000
- API 文档：http://localhost:8000/docs

**验收：**

```powershell
cd backend
python scripts\e2e_acceptance.py
# 预期: 13/13

cd ..
docker compose exec backend pytest tests/ -v
# 预期: 63 passed, 2 skipped
```

**前端 E2E（可选，需本机 Node）：**

```powershell
cd frontend
npm run e2e
# Playwright 会自动拉起 dev；全 Docker 场景也可用容器化前端 + 单独跑 e2e
```

## 场景 B：后端 Docker + 本地前端（开发调试）

适合：日常改 UI、热更新、Playwright 自动 dev。

```powershell
cd E:\AI知识平台\knowflow-ai

# 1. 仅基础服务 + 后端 + Celery
docker compose up -d postgres redis chromadb backend celery-worker

docker ps
# 此时通常无 knowflow-frontend
```

**健康检查：**

```powershell
curl http://localhost:8000/api/health
```

**本地前端：**

```powershell
cd frontend
npm install
npm run dev
```

- 访问：http://localhost:3000
- Vite 将 `/api` 代理到 http://localhost:8000（见 `vite.config.ts`）

**验收：**

```powershell
cd ..\backend
python scripts\e2e_acceptance.py

cd ..
docker compose exec backend pytest tests/ -v

cd frontend
npm run test:run
npm run e2e
```

## 注意事项

### `.env`

| 项 | 说明 |
|----|------|
| 必填 | `SECRET_KEY`（生产 ≥ 32 字符）、`LLM_API_KEY`（问答）、数据库/Redis 由 compose 注入时可沿用默认 |
| 任务队列 | `TASK_BACKEND=celery`（与 celery-worker 一致） |
| 安全 | **切勿**将 `.env` 提交 GitHub（已在 `.gitignore`） |

首次部署可复制：

```powershell
copy .env.example .env
# 或 copy .env.development.example .env
```

### 前端

| 模式 | 访问 |
|------|------|
| Docker | `knowflow-frontend`，映射 **3000:80** |
| 开发 | `npm run dev`，默认 **3000**，代理后端 **8000** |

### 数据卷

`backend` 与 `celery-worker` **共用** `knowflow_uploads_data`，文档处理依赖此卷，勿单独只启 backend 却不启 celery。

### 生产 Nginx

```powershell
docker compose --profile production up -d
```

- 服务：`knowflow-nginx`
- 端口：`NGINX_PORT`（默认 80）
- 配置：`nginx/nginx.conf`

### 全栈验收基线（参考）

```text
e2e_acceptance.py     13/13
pytest (容器内)        63 passed, 2 skipped
npm run build          pass
npm run test:run       19 passed
npm run e2e            4 passed
```

## 快速排错

| 现象 | 处理 |
|------|------|
| `no configuration file` | `cd` 到含 `docker-compose.yml` 的目录 |
| backend unhealthy | `docker compose logs backend --tail 50` |
| 文档一直 processing | 确认 `celery-worker` 在跑且 `TASK_BACKEND=celery` |
| 前端连不上 API | 开发模式确认 backend 8000；Docker 模式访问 3000 非 5173 |
| Chroma 连不上 | 容器内用 `CHROMA_HOST=chromadb`、`CHROMA_PORT=8000` |

更多见 [12-排错.md](./12-排错.md)。

**服务器上线前**请完成 [17-上线前检查清单.md](./17-上线前检查清单.md)。

生产统一入口：

```powershell
.\deploy_all.ps1 -Production
```
